# 사용자 안내 문구 규칙

스낵바·토스트·모달·인라인 안내·에러 메시지 등 **화면에 그대로 노출되는 한국어 문구**를 새로 쓰거나
고칠 때 적용한다. 코드 주석, 커밋 메시지, 개발 문서에는 해당하지 않는다.

## 1. 기호를 넣지 않는다

| 금지 | 대신 |
| --- | --- |
| 대시를 구분자로 (`-`, `–`, `—`) | 문장을 마침표로 끊거나 값은 소괄호에 넣는다 |
| 백틱 `` ` `` | 그냥 평문으로 쓴다 |
| 별표 `*`, 밑줄 `_` 강조 | 강조가 필요하면 컴포넌트로 처리한다 |
| 이모지 | 넣지 않는다 |

```ts
// ❌ 기호가 섞인 문구
`파일이 너무 큽니다 - ${filename}`
`지원하지 않는 형식입니다 — \`${filename}\``

// ✅
`파일이 너무 큽니다 (${filename})`
```

파일명·개수·이름 같은 값을 문구에 넣을 때는 **소괄호**를 쓴다. 값이 문장 주어로 자연스러우면
`${filename} 업로드에 실패했습니다` 처럼 앞에 두어도 된다. 둘 중 하나로 하고 대시로 잇지 않는다.

## 2. 기존 문구를 먼저 찾아본다

새 문구를 짓기 전에 같은 상황의 기존 문구가 있는지 본다. 있으면 그 어투를 따른다.
이 저장소의 문구는 **완결된 문장 + 마침표 + 필요하면 다음 행동 안내** 형태다.

```
예:
"문서를 열 수 없습니다. 옮겨지거나 지워졌는지 확인하세요."
"폴더 연결이 끊겼습니다. 다시 연결하세요."
```

위 예시는 프로토타입 문구라 아직 판정 전이다.

- 서술은 `~습니다`, 행동 요청은 `~하세요` / `~해주세요` 로 맞춘다. 한 화면 안에서 섞지 않는다.
- 원인만 알리고 끝내지 말고, 사용자가 할 수 있는 일이 있으면 한 문장 덧붙인다.
- 서버 내부 용어(`store_name`, `vector_store`, 색인 같은 구현 어휘)를 그대로 노출하지 않는다.

찾는 방법은 `message:` 나 문구 상수 파일(`*.constants.ts`)을 훑는 것으로 충분하다.

## 3. 문구가 이미 확정된 작업이면 글자 그대로 쓴다

기획·설계 문서(`.claude/docs/**`)에 문구 표가 있으면 그 문자열을 **글자 단위로** 옮긴다.
기호를 더하거나 어미를 바꾸지 않는다. 테스트의 단언도 문자열 전체를 비교한다.

문서에서 문구를 백틱으로 감싸지 않는 것도 같은 이유다. 감싸면 그 기호가 실제 문자열에 섞여 들어간다.

## Why

이전 프로젝트에서 업로드 실패 문구를 원인별로 나눌 때, 설계 문서가 문구를
`` `지원하지 않는 형식입니다 (${filename})` `` 처럼 백틱과 템플릿 변수로 적어두었다.
구현된 문구에 대시와 백틱이 그대로 섞여 나와 PR 을 되돌렸다.

기호가 섞인 문구는 기능상 동작하기 때문에 리뷰에서 놓치기 쉽고, 화면에 뜬 뒤에야 드러난다.
문구를 쓰는 시점에 한 번 막는 편이 싸다.
