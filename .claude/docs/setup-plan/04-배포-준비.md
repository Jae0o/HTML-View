# 04 배포 준비

## 목표

Vercel 화면에서 저장소만 가져오면 별도 설정 없이 배포되는 상태인지 확인한다. 설정 파일(`vercel.json`)은 만들지 않는다.

## 왜 설정 파일이 필요 없나

- Vercel 이 Vite 프로젝트를 알아서 인식한다: 빌드 `npm run build`, 출력 폴더 `dist`.
- 화면이 한 장이고 주소 이동(라우터)이 없어서, 새로고침 시 404 를 막는 되돌림 설정이 필요 없다.
- 서버 · 환경 변수가 없다.

## 단계

1. `.gitignore` 에 `node_modules` · `dist` 가 있는지 확인한다 (템플릿 기본값). 없으면 더한다.
2. 새로 받은 상태와 같게 `rm -rf node_modules dist && npm ci && npm run build` 를 실행한다.
3. `npx vite preview --port 4173 --strictPort &` 로 띄우고 아래 「확인」 명령으로 응답을 본 뒤 `pkill -f 'vite preview'` 로 끈다. `npm run preview &` 의 프로세스만 끄면 서버가 남는다.
4. 사람이 할 Vercel 화면 절차는 하지 않는다. 보고에 「사용자 작업」으로 아래를 그대로 적는다.

## 사용자 작업 (Vercel 화면)

1. 첫 커밋을 만든다 (`.git` 이 없으면 먼저 `git init`). 원격 저장소가 연결돼 있지 않으면 `git remote add origin <주소>` 후 push 한다.
2. Vercel 에서 Add New → Project → 저장소 Import.
3. Framework Preset 이 Vite 로 잡혔는지만 확인하고 Deploy.
4. 배포 주소에서 `0Docs` 글자와 탭 아이콘이 보이는지 확인한다. 「폴더 추가」 확인은 프로토타입을 옮긴 다음 플랜에서 한다.

## 확인

- [ ] `npm ci && npm run build` 통과
- [ ] `curl -s localhost:4173 | grep -o '<title>0Docs</title>'` 한 줄
- [ ] `curl -s localhost:4173/favicon.svg | grep -c '#10b981'` 가 1 — 미리보기는 없는 주소에도 200 을 돌려주므로 내용으로 확인한다
- [ ] 보고 끝 「사용자 작업」에 `.git` · 원격 저장소 유무에 맞는 절차가 적혀 있다
- [ ] 확인이 끝난 뒤 `curl -s localhost:4173` 이 응답하지 않는다 (미리보기 서버 꺼짐)
- [ ] 저장소에 `vercel.json` 이 없다
