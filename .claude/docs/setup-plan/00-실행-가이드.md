# 00 실행 가이드 — 0Docs 프로젝트 기본 세팅

모든 태스크 프롬프트가 먼저 이 문서를 읽는다. 태스크 문서보다 이 문서의 공통 규칙이 앞선다.

## 프로젝트 요약

- 서비스: 0Docs — 로컬 html-docs 폴더의 HTML 문서를 모아 보는 웹 뷰어.
- 원본: 채팅 아티팩트 「HTML 뷰어 프로토타입」(단일 HTML). 이 세팅이 끝나면 React 로 옮긴다.
- 서버 없음. 폴더는 브라우저 폴더 선택(File System Access API)으로 읽는다.
- 배포: Vercel 정적 호스팅. Vercel 화면에서 저장소를 가져와 배포한다 (CLI · 설정 파일 없이).

## 기술 구성 (2026-11-19 결정)

| 항목 | 값 |
|---|---|
| 빌드 | Vite (`react-ts` 템플릿) |
| UI | React + TypeScript |
| 상태 | Zustand |
| 스타일 | Tailwind CSS v4 (`@tailwindcss/vite`) |
| 린트 | 템플릿 기본 `oxlint` 그대로 |
| 코드 정렬 | Prettier + `prettier-plugin-tailwindcss` |
| 글꼴 | Pretendard — npm 패키지 `pretendard` 로 함께 배포 |
| 패키지 매니저 | npm |
| 서버 · 라우터 · API 클라이언트 | 쓰지 않음 |

버전은 설치 시점의 최신을 쓴다. 템플릿이 고정한 버전은 바꾸지 않는다.

## 디자이너 판정 (2026-11-19)

- Tailwind 작성 규칙 6개 — O. 토큰 클래스만 쓴다 · 토큰에 없는 너비 · 높이는 rem 대괄호(`w-[36rem]`) · px 직접 금지(화면 폭 조건 예외) · 색 값을 클래스에 직접 쓰지 않는다 · 나란한 요소 사이는 `gap` · 버튼 · 입력 칸 둥글기 6px.
- 규칙 문서 없는 글자 · 색 · 그림자 · 겹침 값을 프로토타입 값으로 쓴다 — O.

## 쓰지 않는 클래스 (FE 보충 — 작성 규칙 「토큰 클래스만」의 풀이)

테마 토큰으로 막을 수 없어 빌드에는 생기지만 쓰지 않는다.

- px 로 나오는 것: `p-px` · `m-px` 등 `-px`, `border-2` 처럼 숫자 붙은 테두리, `rounded-full` (알약은 `rounded-pill`), `outline` · `ring` · `outline-2` · `ring-2`, `underline-offset-*` · `decoration-<숫자>`, `blur-*` · `drop-shadow-*` · `inset-shadow-*`, 대괄호 px (`[12px]`).
- `html` 62.5% 때문에 크기가 작아지는 것: `max-w-sm` · `w-sm` 같은 이름 너비 (`--container-*`, 예: `sm` 384px → 240px).
- 규칙 문서에 없는 글자 간격 · 줄 높이: `tracking-*` · `leading-*` (줄 높이는 `text-base` · `text-sm` 에 이미 들어 있음).
- 필요하면 토큰을 먼저 더하자고 보고한다.

## 플랜 위치

- 플랜 · 프롬프트는 저장소 안 `.claude/docs/setup-plan/` 에 있다. 사람용 HTML 문서는 `~/html-docs/one-oi/049-create-html-viewer/` 에 있다.
- 진행 순서는 기초(이 셋업) → 공통 컴포넌트 → 기능이다. 공통 컴포넌트 · 기능 플랜은 셋업이 끝난 뒤 따로 만든다.
- 저장소에 `.claude/` 가 있으므로 01 단계 1은 임시 폴더 방식으로 만든다.

## 실행 순서

태스크는 번호 순서대로 하나씩 실행한다. 한 태스크가 끝나면 멈추고 보고한다. 다음 태스크는 사용자가 요청할 때 시작한다.

1. `01-프로젝트-생성.md`
2. `02-tailwind-디자인-토큰.md`
3. `03-코드-정렬-도구.md`
4. `04-배포-준비.md`

## 공통 규칙

1. 시작 전에 저장소의 `CLAUDE.md` 와 `.claude/docs` 안의 다른 규칙 문서(이 플랜 폴더 말고)가 있으면 읽고 따른다. 이 가이드와 다르면 저장소 문서를 따르고, 다른 점을 보고에 적는다.
2. 화면 · 스타일 코드를 쓰기 전에 `design-system` Skill 을 읽는다 (`references/00-시작.md` 행동 규칙).
3. 태스크 문서에 없는 것은 만들지 않는다. 쓰지 않는 파일 · 설정 · 추상화를 미리 만들지 않는다.
4. 각 태스크의 「확인」 항목을 직접 실행해 결과를 보고한다. 실패하면 고치고 다시 확인한다. 「사용자 확인 (눈으로)」 항목은 실행하지 않고 보고 끝에 그대로 옮겨 적는다.
5. 커밋 · 푸시는 하지 않는다. 사용자가 요청할 때만 한다.
6. 패키지 매니저는 태스크 문서에 적힌 것만 쓴다. 다른 lock 파일을 만들지 않는다.
7. 서비스명 · 업체명을 코드 주석 · 문서에 새로 넣지 않는다 (0Docs 제외).

## 보고 형식

태스크마다 끝에 아래를 남긴다.

- 한 일: 바뀐 파일과 이유 한 줄씩
- 확인 결과: 「확인」 항목별 통과 / 실패
- 사용한 규칙 (O/X 로 고를 수 있게): 어느 문서의 어떤 규칙을 따랐는지
- 확인 대상 (O/X 로 고를 수 있게): 규칙에 없어서 정하지 않고 넘긴 것
- 저장소 문서와 이 가이드가 달랐던 점 (있으면)
